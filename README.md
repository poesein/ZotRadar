# ZotRadar 5.2.21

ZotRadar 是面向 Zotero 10 的本地文献雷达：按订阅源抓取论文，用可编辑的评估卡判断相关范围与证据强度，汇总为可排序的阅读优先分，并在 Zotero 原生窗口中完成检索、反馈和导入。[English](README_EN.md)

这个公开分发版只内置一个示例方向——**Protein Design（蛋白设计）**，它也是全新安装的默认订阅与评估卡。其他研究方向、重点作者、个人反馈、数据库和 API 密钥均不随安装包提供。用户可以在原生面板中自行创建订阅、订阅源和评估卡；评分程序本身不限定蛋白设计。

> 版本边界：5.2.21 的源码与 XPI 经过离线结构、语法、配置和隐私检查；**尚未在一份全新 Zotero 10 用户资料中完成端到端安装、抓取和模型评分验收**。不要把静态测试视作实机通过。

## 下载与安装

1. 下载 `ZotRadar-5.2.21-zotero10.xpi`，可用 `SHA256SUMS.txt` 核对文件哈希。源码 ZIP 不是安装包。
2. 先备份 Zotero 数据目录，在 Zotero 10.0.x 的插件管理器中从文件安装 XPI，然后完整退出并重启 Zotero。不要手工覆盖 `extensions.json`、插件注册表或 SQLite 文件。
3. 打开 ZotRadar 独立窗口，确认「文献、订阅、评分、反馈、系统」页面可用，并在「系统」页查看启动与数据库状态。
4. 在插件设置中填入你自己的 Ollama 地址和模型。默认示例为本机 `http://127.0.0.1:11434`、`qwen3:8b`；需要模型服务器实际运行且安装相应模型。`easyScholar` 密钥可选，未配置时不显示虚构的 IF 或分区。
5. 先用少量论文测试抓取、评分、反馈和导入，再决定是否开启自动运行。

这是同一扩展 ID `zotradar@poesein` 的升级。**升级现有安装不会删除或替换 Zotero 数据目录中已有的订阅、评估卡覆盖、反馈、历史评分或本地偏好**；因此已有用户可能仍看到自己的旧方向与作者列表。要体验只有蛋白设计的出厂配置，应使用干净的 Zotero 测试资料，或自行备份后在界面中清理个人配置。不要为了换默认方向直接删除整个 Zotero 数据目录。

## 工作方式

| 部分 | 用途 |
| --- | --- |
| 订阅 / Feeds | 将一组抓取源绑定到一张评估卡；示例提供 Europe PMC 的已发表论文与预印本两个源。 |
| 评估卡 | 定义 DIRECT、CONTEXTUAL、TRANSFERABLE、OUT_OF_SCOPE 的领域边界、主题、别名与排除项，可复制或编辑。 |
| 评分 | 模型先提取论文主问题、核心对象、证据类型与深度、支持原句和未知项；程序核查证据并给出范围、强度、相关性分。 |
| 文献 | 搜索、按等级/范围/导入状态筛选，按优先分、日期或 IF 排序，查看细节、批量操作及重新评分。 |
| 反馈 / Profile | 确认或纠正判断，修改/撤销反馈，查看成熟度、重建和回滚版本。反馈后的重算可复用已有模型结果。 |
| 系统 | 查看本地模型、数据库、easyScholar、API、运行记录及旧库迁移入口。 |

等级与分数是阅读排序辅助，不是论文质量、实验真实性或临床价值的保证。模型只应依据标题/摘要判定可见证据；缺少关键内容时可保留待判定状态。IF/分区来自可选的 easyScholar 查询及本地缓存，不应拿它们代替研究相关性。重新评分会请求模型；反馈纠正后的重算通常不重新请求模型。中文译题也使用已配置的筛选模型并会缓存。

## 界面与设置

- 文献标题默认打开 PubMed 标题检索，也可设置为优先 DOI；作者可跳转 Google Scholar，DOI 在详情页提供链接。链接平时无下划线，悬停时显示。
- 标题下显示前两位和后两位作者；用户自行配置的重点作者以浅蓝色突出。公开版重点作者列表为空。
- 可切换中文译题、范围列、主题列；文献页还有已读状态、已导入状态及多选操作。开关切换后会即时保存并刷新视图。
- 原生面板是正式入口；`/zotradar/` 浏览器页面仅保留开发/兼容用途。两者通过同一 Service Layer 访问本地数据。
- Local HTTP API 位于 Zotero 本机服务器的 `/zotradar/api/*`。修改操作需要插件生成的本地 token；**不要把 Zotero 本地 API 端口暴露给公网，也不要分享带 token 的 URL、日志或截图**。

## 数据、隐私与迁移

安装包只有程序资源和公开示例配置，不包含个人论文库、PDF、反馈记录、用户评估卡、个人作者名单、服务器内网地址或密钥。运行时数据写在用户自己的 Zotero 数据目录中；卸载/升级与清理该目录是不同操作。模型请求会发往你在设置中指定的 Ollama 服务，期刊查询则会访问 easyScholar（仅在配置密钥并使用该功能时）；抓取源访问 Europe PMC。使用远程模型或第三方服务前，请自行确认网络与数据政策。

「系统」页的旧版数据库迁移用于显式选择旧库，旧文件只读，导入端采用事务与指纹防重复。**不要将含私人文献或评分的数据库作为 bug 附件公开上传**。迁移前做备份并在测试资料中先验证；历史评分沿用其原始语义，不会自动按新评估卡重新判定。

公开包的文件范围与隐私审计方法见 [发布审计](RELEASE_AUDIT.md)。发现泄露风险时请先通过私密渠道联系维护者，不要创建带密钥的公开 issue。当前仓库没有声明开源许可证；公开可查看源码不等于授予再分发或修改许可。

## 构建与验证

运行时 XPI 的根目录仅包含 `manifest.json`、`bootstrap.js`、`prefs.js`、`config/`、`content/`、`locale/` 与 `web/`。源码 ZIP 另含本文、英文文档、审计报告和公开测试；历史研究报告、真实数据库及用户资料不进入发布物。

```powershell
node --test tests/public-release.test.mjs tests/scoring.test.mjs
```

上述检查验证出厂订阅/Feed/评估卡关系、版本、敏感字符串与文件范围，不能替代 Zotero 原生 UI、模型服务、期刊 API、真实迁移和更新流程的实机测试。问题反馈请提供 Zotero 版本、ZotRadar 版本、可复现步骤及**脱敏**错误，不要附上数据库、访问密钥或私人论文。
